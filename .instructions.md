## DOA Migration — Custom Instructions

These instructions apply to ALL Copilot interactions in this workspace.
They enforce the target platform, security standards, and coding conventions
for the DOA on-prem to Azure migration.

---

### Target Platform
- Azure Container Apps for web workloads (NOT AKS — we want serverless containers)
- Azure Container Apps Jobs for batch/scheduled workloads (replacing K8s CronJobs)
- Azure SQL Database (PaaS) for data tier (replacing on-prem SQL Server)
- Microsoft Entra ID replacing Ping SSO (external) + LDAP (internal auth)
- Azure Communication Services replacing on-prem SMTP relay
- Azure Front Door replacing F5 load balancer
- Azure Container Registry (ACR) replacing on-prem Harbor registry
- Azure Blob Storage replacing on-prem NFS file shares
- Power BI Paginated Reports replacing SSRS

### Code Standards
- .NET 8 with minimal hosting model
- Serilog for structured logging — replace ALL Console.WriteLine with proper ILogger/Serilog calls
- Use Azure.Identity (DefaultAzureCredential) for all Azure service authentication
- Use Managed Identity everywhere — no connection strings with passwords
- Health checks required on all web apps (/healthz endpoint)
- Configuration via Azure App Configuration + Key Vault references

### Security Requirements
- No secrets in appsettings.json, environment variables, or code
- All secrets must be stored in Azure Key Vault, referenced via Key Vault provider
- Use parameterized queries — no string concatenation for SQL (fix existing SQL injection vulnerabilities)
- Enable Azure Defender for SQL
- All HTTP traffic over TLS 1.2+
- Fix all SQL injection vulnerabilities found in existing code

### Container Standards
- Multi-stage Dockerfile (build stage with SDK image + runtime stage with ASP.NET image)
- Non-root user in production containers
- Expose health check endpoint in Dockerfile
- Use .dockerignore to minimize image size
- Pin image tags (no :latest)

### Naming Conventions
- Resource groups: `rg-doa-{env}` (e.g., rg-doa-prod)
- Container Apps: `ca-doa-{component}-{env}` (e.g., ca-doa-web-prod)
- Container Apps Jobs: `caj-doa-{job}-{env}` (e.g., caj-doa-batch-prod)
- Azure SQL: `sql-doa-{env}` (e.g., sql-doa-prod)
- Key Vault: `kv-doa-{env}` (e.g., kv-doa-prod)
- Container Registry: `acrdoa{env}` (e.g., acrdoaprod)
- Front Door: `fd-doa-{env}`

### IaC Standards
- Bicep as the IaC language (not Terraform, not ARM)
- All resources in a single resource group per environment
- Use Bicep modules for reusable components
- Parameter files for environment-specific values
- Output connection info needed by GitHub Actions deployment

### CI/CD Standards
- GitHub Actions for CI/CD (migrate from self-hosted to GitHub-hosted runners)
- Use OIDC federation for Azure auth in GitHub Actions (no service principal secrets)
- Separate build and deploy jobs
- Push container images to ACR (replacing Harbor)
- Use `az containerapp update` for deployment
